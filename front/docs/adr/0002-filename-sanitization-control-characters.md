# 0002: ファイル名サニタイズでC0制御文字を意図的にマッチさせる

## Status

Accepted

## Context

`front/src/lib/download.ts` の `sanitizeFilename()` は、プリセット名を
ダウンロードファイル名として使えるようにサニタイズする。正規表現
`/[<>:"/\\|?*\u0000-\u001f]/g` は、Windows で予約されている記号
(`<>:"/\|?*`) に加えて、C0 制御文字 (`\u0000`–`\u001f`) も意図的に
置換対象へ含めている。プリセット名は `.flp` ファイル内の任意バイト列に
由来するため、制御文字がファイル名にそのまま混入する経路を塞ぐ目的である。

oxlint の `no-control-regex` ルール (`correctness` カテゴリ、severity: error)
は、正規表現リテラル内に制御文字が含まれることを一律に検出する。この検出は
今回のケースでは偽陽性だが、`front/AGENTS.md` によりコード内コメント
(インラインの `oxlint-disable-next-line` を含む) およびlint設定でのルール
無効化は認められていないため、ルールに抵触しない実装へ変更する。

## Decision

制御文字の判定を正規表現から分離する。Windows 予約記号のみを正規表現
`/[<>:"/\\|?*]/`(制御文字を含まないため `no-control-regex` の対象外)で
判定し、制御文字 (`\u0000`–`\u001f`) は文字コード比較 (`charCodeAt(0) <= 0x1f`)
で判定する。両方に該当する文字を `_` に置換する。

## Consequences

- lint設定・インラインコメントのいずれも変更せず、`no-control-regex` は
  全ファイルで通常通り `error` のまま有効。
- 制御文字判定を追加・変更する場合は、正規表現リテラルへ制御文字を
  直接書き込まず、文字コード比較で行うこと。
